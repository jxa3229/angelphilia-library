# 交付验证约定

- 提交前核对当前分支、未提交文件和远端实际主分支；本仓库主分支为 `main`，不得把口头简称误作新建 `master` 的要求。
- GitHub Pages 工作流包含 `npm audit --audit-level=moderate`。2026-11-17 交付时发现旧锁文件有 6 项高危漏洞，使用不带 `--force` 的 `npm audit fix --ignore-scripts --no-fund` 在现有依赖版本范围内更新锁文件，审计结果降为 0；不得通过降低审计级别或跳过检查交付。
- 依赖更新后重新运行 Node 单元测试、身体部件数据校验、Vite 生产构建和页面 smoke 测试；开发服务应使用更新后的依赖启动。
- 筛选后立即切换窄屏时，先等待 `.el-select__popper:visible` 归零，再检查页面宽度。曾复现下拉框退出动画仍保留桌面坐标、导致即时宽度断言误报；通过 DOM 关闭状态等待解决，不用固定延时或隐藏页面溢出来掩盖问题。
- 本地验证已有资料时，可使用 Vite 的 `build({ build: { write: false } })` 检查编译，避免 `npm run build` 的资料同步阶段覆盖正在整理的数据。该检查不代替线上工作流的完整资料同步与发布构建。
- 小红书封面属于本地交付文件，验证截图属于本地证据；提交代码时保留文件并排除提交，不把临时验证配置、报告或进程带入仓库。已跟踪的历史文件不据此批量删除。
