# 卡片组件复用约定

## 商品卡片与详情

- `src/components/shared/CatalogCard.vue` 是统一商品卡片，只显示图片、年份和名称，接收 `image`、`year`、`name`，通过 `open` 事件交由调用方打开详情。馆藏、限定、外装、配件预览和素体展览共用该组件。
- `RecordCard.vue` 只负责馆藏数据适配、封面选择和名称本地化；不得重新添加标签、规格、简介等卡片下半部分。
- 没有明确年份时使用当前语言的未知值，不从商品编号、图片路径、抓取时间或售价推断年份。商品数据后续补入 `year` 字段即可展示。
- 图片保持完整比例；缺图或加载失败显示当前语言的无图提示。图片和名称均可用鼠标、键盘打开详情。
- `RecordMetadata.vue` 集中展示馆别、系列、编号、版本、肤色、头型号、头部、身体及限定分类，加载正文失败时仍可读取这些字段。商品标题继续保留在详情页头部。
- `MetadataList.vue` 复用详情字段布局；外装、配件及素体展览使用 `ProductDetailDrawer.vue`，图片查看复用 `ProductGallery.vue`。配件尺寸、工艺、来源、价格与相关档案链接放在详情，不从卡片移除后丢失。
- 共用画廊支持翻页和点击放大，原有图片地址、来源链接及业务筛选保持独立。

## 其他卡片

- 统计卡片使用 `StatCard.vue`，店铺入口使用 `ShopLinkCard.vue`，配件尺寸摘要使用 `PartMeasurementCard.vue`。
- 统计、店铺链接及选中配件尺寸属于信息组件，保留其数值、链接和选中状态，不伪造商品图片或发行年份。
- 筛选、抽屉开关、当前商品和业务数据由调用方持有，基础组件不直接操作路由或全局馆藏状态。
- 卡片基础样式收在组件内；小型展示通过 `--catalog-image-height`、`--catalog-card-padding`、`--catalog-title-size` 调整，避免重复维护整套 CSS。

## 验收

1. 各商品列表只出现图片、年份、名称；规格可在详情中找到。
2. 图片和名称打开同一商品；关闭详情保留列表筛选，馆藏返回保留滚动位置。
3. 限定档案语言切换继续生效，分类放在详情中。
4. 外装及配件详情包含原有字段、尺寸、来源和相关记录；画廊可翻页、放大。
5. 桌面和窄屏没有新增横向溢出，暗色与亮色主题沿用项目变量。
6. `tests/smoke.spec.js` 覆盖主要路由、简化卡片与完整详情、限定翻译、外装和配件抽屉、手机端排列。

构建验证应使用 Vite 的 `build({ build: { write: false } })`；不要为检查组件而重新生成资料或覆盖现有静态资源。浏览器回归复用已启动的本地 Vite 服务，临时配置与报告在完成后清理。

Hash 路由回归须在刷新后等待首页标题出现，再切换目标路由。`page.reload()` 完成不代表 Vue Router 已初始化；紧接着修改 hash 可能被初始化导航覆盖，表现为仍停留首页。用可见元素断言同步，不通过固定延时或放宽断言掩盖。

Windows 长时间运行的预览服务若继续返回旧组件，先对照磁盘源码与 `/src/...vue` 的实际 HTTP 内容，确认 Vite 文件监听是否失效。仅重启当前项目的服务，可在 `server.watch` 中启用 `usePolling: true`；不要用重新生成资料或创建副本绕过。页面切换后先等待目标页面容器出现，再检查卡片数量，避免把上一页尚未卸载的卡片计入结果。
