# 限定档案维护说明

## 内容入口

- 页面：`src/pages/LimitedPage.vue`，路由 `/#/limited`。
- 分类规则：`src/utils/limitedRecords.js`，从馆藏名称、标题与明确的角色合作字段派生分类。
- 官方补档：`src/data/limitedOfficial.json`，由官方商品页标题、主图及日文规格摘录整理，进入统一馆藏与限定栏目。
- 释义与参考来源：`src/data/limitedGuide.js`；品牌术语页同步维护 `src/data/brandGlossary.js`。
- 多语言展示：`src/i18n/limited.js` 维护限定页中、英、日文案及规格术语；`src/data/limitedTranslations.js` 维护官网补档的中文、英文人工翻译。日文来源数据保留在 `limitedOfficial.json`，不覆盖。
- 早期系列名通过 `src/utils/recordNames.js` 统一为 `ONE SELECTION DOLL #编号`，在 store 入口应用，避免重新生成数据后恢复旧名称。只改展示字段，不改历史目录、来源链接和图片路径。
- 限定卡片与馆藏共用 `RecordCard` → `CatalogCard`，仅显示图片、年份和名称；OSD/FCD/联动分类与其他规格统一收进 `RecordMetadata` 详情字段，筛选页签继续保留分类入口。通用组件约定见《卡片组件复用约定》。

## 口径与来源核对

1. OSD 为官方定义的 One-off 手工定制人偶。FCD 基于量产角色本体进行限定整体搭配；不能据此认定完整 FCD 一定不具备一点物属性。官方 FCD EMMA 页也使用「ワンオフ」，并明确「１体のみの抽選販売品」。分类应体现创作重点，不以“抽选”一词自动归为 OSD。
2. OSD 商品编号以页面标题和内容为准，不能从 URL 路径推断。实际发现：`one-selection-doll-115【ワンオフ抽選販売品】-8780.html` 的当前页面标题是 **ONE SELECTION DOLL #119**，补档使用 #119，并保留原链接。
3. 公开编号已见 #125，不等于已核实发行总量恰好为 125；线下展品、独立编号及衍生企划不可简单相加。页面计数始终表示本站实际收录数量。
4. 角色联动根据馆藏明确的角色合作字段识别，保留 Catwoman 等历史产品；正文中“非联动”不构成收录依据。限定栏目包含角色合作档案，并不宣称每个联动款都是限量或孤品。
5. 新增官方档案先核对标题、实际编号、原始链接与图片归属，避免与原馆藏重复；年份来自对应官方发布图片目录，属于发布资料的年份线索，不代表已独立确认发售日期。历史商品不标为当前可购买。
6. 官方补档图片保留官方远程来源，显示依赖官网可用性；不伪造本地图片或缺失规格。
7. 跨栏目复用 `RecordDetail` 时，通过 store 公开的 `loadDetails(record)` 加载正文；限定页独立维护详情及筛选状态，避免使用全局 `openRecord` 把限定页状态带入普通馆藏。浏览器回归须检查 `pageerror`，不能仅凭标题出现认定正文加载成功。
8. 切换语言时，列表、筛选、对照表、编号沿革和补档详情同步更新，保持当前筛选及打开的商品。早期档案先展示当前语言摘要，完整历史资料保留在可展开的「详细资料与来源」中；未逐段校译的历史长文不冒充完整译文。妆师名、品牌、型号、尺寸、材料标记和原始来源链接须保留；翻译规格时不可补造缺失配置或擅自修正来源的材料缩写。

## 验证

- 执行 `node --test tests/limited-records.test.mjs`，覆盖早期日文名称、FCD 拼写、普通抽选误分类、角色合作、搜索别名及 URL 旧编号问题。
- 构建验证路由与模块；浏览器验证分类计数、交叉搜索、空态重置、详情返回及筛选状态保留、三语菜单、主题和窄屏表格滚动。
- 仅创建补档数据，不直接手工改写生成的 `src/data/records.json`；保留原馆藏、原有工作区改动和来源链接。
