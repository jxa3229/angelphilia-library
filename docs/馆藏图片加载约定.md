# 馆藏图片加载约定

- 馆藏每批显示 24 条，“加载更多条目”追加下一批；顶部统计与搜索、馆别、年份、来源、头型及肤色筛选始终作用于完整数据。筛选变化重置批次，语言变化保留批次；详情返回保留展开数量和桌面/手机滚动位置。
- 前 4 张馆藏卡片 eager / high 加载，其他 lazy；图片异步解码、保留固定容器与完整比例，避免加载时布局跳动。
- `CatalogCard.vue` 区分加载、成功、无图和失败；缓存封面失败先回退原图，最后失败最多自动重试一次（600ms），随后显示手动重试。卸载或更换图片时清理计时器；手动重试不打开详情。不要重新采用首次失败后永久隐藏图片的策略。
- 远程馆藏封面映射维护在 `src/data/catalogCovers.json`，正式缓存资源在 `public/catalog-covers/`，按来源 URL 的 SHA-256 前缀命名。源档案和原始画廊不改写。缓存为本次正式交付资源，应随代码纳入版本管理。
- 显式运行 `npm.cmd run cache:catalog-covers` 更新缓存；需要已有代理时只为该命令设置 `CATALOG_IMAGE_PROXY`，不得改系统或 Git 代理。脚本最多 4 路下载、有超时和有限重试、检查图片魔数、复用有效文件。失败返回非零且保留既有缓存；不把外网下载加入 dev/build。
- `node scripts/cache-catalog-covers.mjs --check` 检查全部当前远程封面映射与本地文件。新增档案后必须更新缓存并再次检查，避免只在自己的网络环境加载成功。
- 回归执行 `node node_modules/@playwright/test/cli.js test tests/library-images.spec.js --workers=1`；覆盖本站封面、批次/全量检索、短暂/持续失败、手动重试、原图回退、详情返回、三语和窄屏。Pages 部署必须额外在 `/angelphilia-library/` 子路径下检查。
- 失败恢复断言先定位目标卡片，再定位其 `img`。不要用整个列表的第一个 `img`：目标失败时图片暂时卸载，会把下一张正常图片误判为恢复成功。缓存验收除文件签名外还应在浏览器中实际解码，不能只检查 HTTP 200。
