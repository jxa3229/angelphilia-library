# 馆藏首屏图片加载优化

## 需求背景

用户反馈首次打开馆藏时图片容易加载不出。检查当前 328 条馆藏：172 张本地封面文件均存在，156 张封面依赖 FC2 / Quarantotto 外站；列表一次挂载 328 张卡片，卡片图片首次失败后不再恢复。

## 方案与边界

- 保持 Vue 3、Pinia、GitHub Pages/hash 路由和资料源数据不变。
- 维护独立封面映射，把已缓存的外站封面通过本站路径提供；下载脚本显式运行，dev/build 不依赖外网。来源 URL 与详情原始画廊保留。
- 馆藏首批 24 条，手动“加载更多”每次追加 24 条；筛选始终覆盖全部馆藏，筛选条件变化重置批次。详情返回保留已展开数量、筛选和桌面/手机滚动位置。
- 首批前 4 张图片使用 eager，其余 lazy，异步解码。公共卡片区分加载、成功、失败；失败最多自动重试一次，随后显示可操作的三语手动重试。缓存路径失败时可回退原始封面，不进行无限重试。
- 仅改进馆藏图片链路和公共卡片的图片恢复能力，不扩大到安全过滤、术语翻译或完整数据架构重构。

## UX 契约

- 入口：侧栏“馆藏条目”或直接访问 `#/library`。
- 主流程：看到首批封面与全量匹配计数 → 加载更多 → 打开条目 → 返回原位置。
- 状态：图片加载时占位；成功完整比例展示；失败明确显示重试按钮；无图片继续显示无图提示。图片重试按钮不打开详情。
- 所有控制文案覆盖中/英/日；触控按钮高度至少 44px；320px 窄屏无新增横向溢出；亮暗主题沿用变量。

## 验收标准

- 现有外站封面缓存清单覆盖 156 条，映射指向真实且有效的本站图片。
- 首批 24 条、追加 24 条；全量搜索仍可找到首批之外记录，无遗漏或重复。
- 模拟一次失败可自动恢复；持续失败显示手动重试；恢复网络后无需刷新页面即可成功。
- 详情返回保留追加批次和滚动位置；筛选重置正确；Pages 子路径、三语、窄屏检查通过。
- Node 单元测试、Playwright 全量回归、部件数据校验与生产编译通过；不提交或推送代码。
